# 黒ウィズ型リデザイン 仕様書

『世界の教室』のゲームサイクルを、『クイズRPG 魔法使いと黒猫のウィズ』の形に
作り直すための仕様です。**調査の根拠は `wiz-research.md`、画面は
`wiz-redesign-screens.md`。** この3つで1組です。

素材は **MyCryptoHeroes**（`bearko/mycryptoheroes`）から採ります。
**名前・スキル名・パラメーターは MCH のものをそのまま使い、こちらで作りません。**

---

## 0. 確認して決めた4つ

着手前に確認を取った分岐です。**この4つが仕様全体の骨格を決めています。**

| | 決めたこと |
|---|---|
| **原則との関係** | **既存の「絶対に守る設計原則」を守り、黒ウィズからは手ざわりだけ写す。** ガチャ・魔力（スタミナ）・レアリティ＝強さは入れない |
| **デッキ** | **黒ウィズ式の5枚編成。** MCHの3人パーティからは離れる |
| **制限時間** | **形式ごとに持ち時間を決め、その中の速さでASの発動本数が変わる。** 報酬は速さで変えない |
| **属性** | **MCHの5勢力（朱雀・玄武・青龍・白虎・黄竜）を属性にする。** 教科6つは別の軸（クイズのジャンル） |

## 1. 原則との突き合わせ — 何を写し、何を写さないか

**黒ウィズの仕組みのうち4つは、このプロジェクトの原則と正面からぶつかります。**
写さない判断と、その穴を何で埋めるかを先に書きます。

| 黒ウィズ | ぶつかる原則 | ここでの扱い |
|---|---|---|
| **ガチャで精霊を引く** | 原則2（ランダム報酬を入れない） | **入れない。** ヒーローは知識カードの枚数と「その人物の問題」で**確定で**仲間になる（§11） |
| **魔力（スタミナ）で挑戦回数を絞る** | 原則4の精神（途切れさせたくない動機を作らない） | **入れない。** 何度でも挑める。挑む理由は知識マップの白いマスが持つ |
| **レアリティと育成が強さ** | 原則1（強さの源は知識であって素材ではない） | **入れない。** ヒーローの攻撃力は**知識カードの網羅率**で決まる（§8）。レアリティが決めるのは**デッキコスト**だけ |
| **SSで選択肢を減らす・時間を止める** | 決定2（降りるかどうかは常にプレイヤーの手） | **入れない。** 難易度のつまみはヒントと「4択に切り替える」がすでに持っている。**SSはクイズに干渉させない**（§6） |

**写すものは次の6つです。** どれも「クイズが戦闘の入力になる」ための部品で、
報酬の出方には触れません。

1. クイズ＝攻撃という1問の流れ（§3）
2. 回答の速さで発動するASの本数が変わる（§4）
3. チェイン（§5）
4. AS と SS の二段構え（§6）
5. 属性相性（§2）
6. 5枚デッキと編成順（§7）

## 2. 属性 — MCHの5勢力と五行相剋

**黒ウィズの火水雷光闇を、MCHの5勢力にそのまま置き換えます。**
MCHのヒーローは全404体が5勢力のどれかに属していて（玄武86・朱雀82・黄竜80・
青龍80・白虎76）、**こちらで属性を作る必要がありません。**

| 勢力 | EN | 五行 | 色（案） |
|---|---|---|---|
| **朱雀** | SUZAKU | 火 | 朱 `#e0503c` |
| **玄武** | GENBU | 水 | 藍 `#2f6fb0` |
| **青龍** | SEIRYU | 木 | 碧 `#2f9b6a` |
| **白虎** | BYAKKO | 金 | 白銀 `#b8bfc6` |
| **黄竜** | KORYU | 土 | 黄土 `#d0a03a` |

### 相性は五行相剋の輪

```
青龍(木) ─▶ 黄竜(土) ─▶ 玄武(水) ─▶ 朱雀(火) ─▶ 白虎(金) ─▶ 青龍(木)
          木剋土        土剋水        水剋火        火剋金        金剋木
```

| | 倍率 |
|---|---|
| 剋す相手へ（有利） | **1.5** |
| それ以外 | 1.0 |
| 剋される相手へ（不利） | **0.5** |

**黒ウィズの数字（1.5 / 1.0 / 0.5）をそのまま使います。**

**光・闇のような「2つだけで閉じた相互有利」は作りません。** 5つが1つの輪に
なっているほうが、どの勢力を選んでも同じだけ有利・不利があり、扱いが揃います。

```js
// src/faction.js（新規）
export const FACTIONS = ["朱雀", "玄武", "青龍", "白虎", "黄竜"];
/** 剋す相手。五行相剋 */
export const BEATS = { 青龍: "黄竜", 黄竜: "玄武", 玄武: "朱雀", 朱雀: "白虎", 白虎: "青龍" };
export const affinity = (a, b) => BEATS[a] === b ? 1.5 : BEATS[b] === a ? 0.5 : 1.0;
```

### 教科は別の軸のまま

**教科（国語・算数・数学・理科・社会・外国語・情報）は属性にしません。**
クエストが教科を持ち、敵が属性を持ちます。**「どの教科を解くか」と
「どの勢力で挑むか」が、別々の判断になります。**

クリスタルの族↔教科の1対1（既存）はそのまま残します。**族と勢力は別物です。**
名前がぶつからないよう、画面では族を「鉱物の族」、勢力を「属性」と呼び分けます。

## 3. 1問の流れ

```
                      ┌──────── 持ち時間（形式ごと・§4）────────┐
問題が出る ──▶ 答える ──▶ 正解 ──▶ チェイン +1
                    │            ├─ AS を 5/4/3/2 体 発動（速さなり）
                    │            ├─ 敵にダメージ（§8）
                    │            ├─ SSゲージ +1
                    │            └─ GUM・知識カード・クリスタル抽選（速さで変わらない）
                    │
                    └──▶ 不正解 / 時間切れ
                                 ├─ チェイン 半減
                                 ├─ 敵の反撃（ヒーローがダメージを受ける）
                                 └─ 知識カード・解説は入る（原則3）
```

**正解したときの報酬は、速さでも、チェインでも、属性相性でも変わりません**（原則3-2）。
**速さ・チェイン・相性・編成が効くのは「敵がどれだけ削れるか」だけです。**

## 4. 持ち時間と回答判定

### 持ち時間は形式ごと

黒ウィズは全形式20秒ですが、**この game には文字パネル（なぞる）や消去法（3回押す）
のように、手数そのものが多い形式があります。** 一律にすると、重い形式だけが
理不尽になります。

既存の `engine.MODE_WORK`（操作の手数）から導きます。

```js
export const SECONDS_PER_WORK = 8;
export const timeLimit = mode => Math.round(MODE_WORK[mode] * SECONDS_PER_WORK);
```

| 形式 | 手数 | 持ち時間 |
|---|---|---|
| スワイプ | 1.0 | **8秒** |
| 4択 | 1.4 | **11秒** |
| 消去法 | 2.0 | **16秒** |
| レンジ | 2.4 | **19秒** |
| 数値入力 | 2.4 | **19秒** |
| 文字パネル | 2.8 | **22秒** |

**1束の中では持ち時間が変わりません**（同じ形式が続くため）。**束が変わると
持ち時間も変わる**ので、接敵画面（W-20）に「◯秒」と出します。

### 判定は持ち時間の4分の1きざみ

黒ウィズは20秒のうち5秒がEXCELLENTの境目です。**比（1/4）のほうを写します。**

| 判定 | 境目 | 発動するAS |
|---|---|---|
| **EXCELLENT** | 持ち時間の 1/4 以内 | **5体** |
| **GREAT** | 1/2 以内 | **4体** |
| **GOOD** | 3/4 以内 | **3体** |
| **NICE** | 持ち時間いっぱいまで | **2体** |

**正解すれば最低2体は発動します**（黒ウィズと同じ）。落ちるのは**デッキの右から**
です（§7）。

```js
export const AS_BY_JUDGE = { EXCELLENT: 5, GREAT: 4, GOOD: 3, NICE: 2 };
export const judge = (ms, limitSec) => {
  const r = ms / (limitSec * 1000);
  return r <= 0.25 ? "EXCELLENT" : r <= 0.5 ? "GREAT" : r <= 0.75 ? "GOOD" : "NICE";
};
```

### 時計を止める3か所

**原則5（ヒントは答えの直前で止める）で渡した道具を使うと罰される、という形に
しないでください。**

1. **ヒントのポップアップを開いているあいだ**は止める
2. **「4択に切り替える」を押したら、その問題の時計を最初から数え直す**
   （形式が変わるので持ち時間も4択のものになる）
3. **設定のポップアップを開いているあいだ**は止める

### 時間切れの扱い

- **不正解と同じ扱いです。** 攻撃できず、チェインが半減し、敵の反撃を受けます
- **知識カードと解説は入ります**（原則3）
- **画面に「時間切れ」とだけ出して、責める文言は足しません。**
  不正解時の文言は既存どおり「面白い単元に当たった」です
- **初回起動（W-01）には持ち時間を置きません。** バトルそのものを立てないためです（決定1）

## 5. チェイン

| | |
|---|---|
| 正解 | **+1** |
| 不正解・時間切れ | **半減**（切り捨て）。0には戻しません |
| ダメージ補正 | `(100 + チェイン) %` |
| 続く範囲 | **1セッションのあいだ。** 束（wave）をまたいでも切れません |
| 表示 | バトル層の**右上**。3桁まで |

**黒ウィズの「誤答で半減」をそのまま使います。** 0に戻す仕様は2017年に
やめられていて、**外した1問がそれまでの積み上げを全部消すのは、原則3と
正面からぶつかります。**

```js
export const chainNext = (chain, ok) => ok ? chain + 1 : Math.floor(chain / 2);
export const chainBonus = chain => (100 + chain) / 100;
```

## 6. AS と SS

**ヒーローとエクステンションで役割を分けます。** MCHのデータ構造がそのまま使えます。

| | 出どころ | 発動 |
|---|---|---|
| **アンサースキル（AS）** | **ヒーローの Passive**（`Data/Heroes/heroes.json` の `passive`） | 正解すると自動。速さで本数が決まる |
| **スペシャルスキル（SS）** | **装備したエクステンションの Active Skill**（`Data/Extensions/extensions.json` の `active_skill`） | ゲージが溜まると自分で押す |

**この分け方は、MCHの「ヒーローにエクステンションを装備して戦う」をそのまま
黒ウィズのAS/SSに当てたものです。** 名前もスキル名も MCH のものを使い、
こちらで作りません。

### 効果の種類は effect_id がそのまま持っている

MCHの `effect_id` が、演出スプライトとSEにそのまま対応します。

| effect_id | 中身 | スプライト | SE |
|---|---|---|---|
| 1 | 単体ダメージ | `Image/Effects/Battle/01_single_damage.png` | `Audio/SE/Battle/1_single_damage.mp3` |
| 2 | 全体ダメージ | `02_area_damage.png` | `2_area_damage.mp3` |
| 3 | 回復・復活 | `03_heal_resurrection.png` | `3_heal_resurrection.mp3` |
| 4 | バフ | `04_buff.png` | `4_buff.mp3` |
| 5 | デバフ・状態異常 | `05_debuff_status_effect.png` | `5_debuff_status_effect.mp3` |

**ヒーローのPassiveは5種類すべてにまたがっています**（バフ159・デバフ98・
全体51・回復51・単体45）。**回復ASもデバフASも、素材を探さずに揃います。**

### ASの発動条件 — MCHの condition を読み替える

MCHのPassiveは発動条件を持っています。**黒ウィズのASにも「3Chain以上」
「HP80%以上」という条件があるので、そのまま対応します。**

| MCHの condition | バトルでの読み替え |
|---|---|
| バトル開始時に | **その wave の1問目に正解したとき** |
| 自身がActive Skillを使用した後に | **その枠が行動したとき（＝正解のたび）** |
| 自身がActive Skillでダメージを受けた後に | **反撃を受けた次の正解** |
| 自身が死亡した後に | **ヒーローが倒れているとき** |
| HPが◯%未満の時に／味方全体のHP合計が◯%未満の時に | **パーティのHPがそこを切っているとき** |
| 1回だけ発動 | **1セッションに1回** |
| `{triggerRate}%の確率で` | **サイコロを振らない。** 問題ID × ヒーローID のハッシュで決める |

**MCH の「Active Skill」は必殺技ではなく、毎ターンの行動そのものです。**
装備したエクステンションの技を毎回撃つのが MCH のバトルなので、
「自身がActive Skillを使用した後に」は**その枠が行動したとき**を指します。
**ここを「SSを撃った次」と読むと、40体のうち23体のASが一生出ません。**

**読み替えられない条件は通します。** 出ないほうへ倒すと、そのヒーローが
ただ弱いだけになります。確率（triggerRate）のほうで十分に絞れています。

### 動いた枠は、必ず一撃を入れます ★

**ASの条件とは別に、出番が回ってきた枠は必ず攻撃します**（`BASIC_RATE` = 0.35）。
ASはその上に乗ります。

**こうしないとバトルが止まります。** 最初の5体は、確率40%の攻撃AS・開始時だけのAS・
回復AS・条件つきのバフASという組み合わせで、**そのままだと1問も敵を削れません**
（実際に止まりました）。MCH でもヒーローは毎ターン必ず殴り、パッシブはその
まわりで条件つきに乗ります。**同じ形にしてあります。**

**確率をサイコロにしないでください。** 既存の `engine.skillChance` と同じ理由です——
運で出るようにすると「出るまで引き直す」遊び方ができ、原則2と正面からぶつかります。
**割合としては triggerRate どおりですが、1問ごとに見れば決まっています。**

```js
export const asFires = (passive, q, heroId, ctx) =>
  conditionMet(passive, ctx) &&
  hash(`${q.id}|${heroId}|as`) % 1000 < (passive.trigger_rate ?? 100) * 10;
```

### SSのゲージ

| エクステンションのランク | 必要正解数 |
|---|---|
| 初伝 | **3** |
| 中伝 | **4** |
| 奥伝 | **6** |

黒ウィズの「未覚醒で最低3回」に合わせています。**発動するとカウントは0に戻ります。**

**ランクは既存の独自ランク（由来がいくつの教科にまたがるか）をそのまま使います。**
MCHのレアリティは使いません（CLAUDE.md の既存の決まり）。

### SSにクイズを触らせない

黒ウィズのSSには「選択肢を減らす」「制限時間を止める」があります。**入れません。**

難易度のつまみ（ヒントを何段使うか・4択へ降りるか）は**決定2でプレイヤーの手に
置いたもの**です。SSがそれを肩代わりすると、**システムが勝手に降ろしている**ことに
なります。**SSが動かすのは、敵とヒーローの数値だけです。**

## 7. デッキ

**5枚編成。** 1枚 ＝ ヒーロー1体＋そこに装備したエクステンション1つ。

```
 ┌────┬────┬────┬────┬────┐
 │ 1  │ 2  │ 3  │ 4  │ 5  │   ← 左が先。右ほどASが落ちる
 └────┴────┴────┴────┴────┘
   ↑各枠   ヒーロー（AS・属性・コスト）
           ＋ エクステンション（SS）
```

### 編成順がルールになる

**ASは左から数えて発動します。** NICE（遅い）なら左の2体だけ、EXCELLENT なら5体全部。
**右に置いた精霊ほど、速く答えないと出番がありません。**

**これは黒ウィズの芯です。** 画面上の並びがそのままルールになっていて、
**「編成順を決める」ことが「どれだけ速く答えるつもりか」の宣言**になります。

### コストと上限

コストはヒーローのレアリティから導きます（**強さではなく枠の重さ**です）。

| レアリティ | コスト |
|---|---|
| Common | 4 |
| Uncommon | 6 |
| Rare | 9 |
| Epic | 13 |
| Legendary | 18 |

**デッキコストの上限は、知識マップの埋まり具合で決めます。**

```js
export const deckCap = (db, state) => 20 + filledCells(db, state);   // 20 〜 68
```

**プレイヤーレベルという数値を新しく作らないでください。** 進行の数値を2つ持つと
必ず食い違います（CLAUDE.md の既存の決まり）。**知識マップが埋まることが、
そのまま編成の自由になります。**

### 超過しても挑める

**コストを超えていても挑戦できます。** そのかわり全ヒーローのパラメーターが
**25%ダウン**します（黒ウィズと同じ）。

**禁止ではなく代償にしてください。** 決定2（降りるかどうかは常にプレイヤーの手）と
同じ形です。画面には「超過 −25%」と出すだけで、止めません。

## 8. ダメージ計算

### ヒーローの一撃

```
一撃 = 基礎攻撃 × 知識倍率 × 超過補正
```

| 項 | 中身 |
|---|---|
| **基礎攻撃** | `engine.heroHit` ＝ MCHの `(phy + int) / 2`。**手で書きません** |
| **知識倍率** | `0.5 + 網羅率 × 1.5` → **0.5倍〜2.0倍** |
| **超過補正** | コスト超過なら 0.75、そうでなければ 1.0 |

**網羅率は `engine.gaugeBreakdown` の「基礎」です** ——
`直結カードの網羅率 × 0.6 ＋ 関連分野の網羅率 × 0.4`。

**装備倍率（`GEAR_MAX`）はここに掛けません。** 掛けると「装備の量＝攻撃力」に
なり、原則1が裏返ります。**エクステンションが効くのはSSの中身だけです**
（＝触媒のまま）。

> **勝手に決めた数字です。** 知識ゼロでも0.5倍は出るようにしました。0にすると
> 始めたばかりの人が1体も倒せません（原則3）。**釣り合いの確認先は
> `review-points.md`。**

### 1問の与ダメージ

```
与ダメージ = Σ（発動したAS）
            AS1本 = 一撃 × ASの効果率 × 属性相性 × チェイン補正
```

```js
export const asDamage = (hit, rate, atkFaction, defFaction, chain) =>
  Math.max(1, Math.round(hit * rate * affinity(atkFaction, defFaction) * chainBonus(chain)));
```

**効果率**（`min_rate`〜`max_rate`）は MCH の値をそのまま使います。**幅があるものは
中央値に固定します** ——乱数にすると、同じ問題で結果が変わり、原則2に触れます。

### 敵の体力と反撃

既存の `engine.foeMaxHp` / `engine.foeHit` の考え方をそのまま使います。

- 敵の体力は**そのwaveの残り問題数から逆算**。`ATTACK_RATE = 0.8`
  （その束の8割に正解したら倒れる）
- **1問目から5体ぶんのASが乗るわけではないので、EXCELLENTを取り続ける前提の
  体力にしないでください。** 基準は「NICE（2体）で0.8割正解」に置きます
- ヒーローが倒れるのはセッション全体の6割を外したあたり（`FALL_RATE = 0.6`）

**ヒーローが倒れてもwaveは続きます。** 1問ごとの報酬は倒れているかどうかで
1つも変わりません（原則3・既存の確定仕様）。

## 9. クエストの構造

**既存の「1セッション＝形式の束3つ」を、そのまま黒ウィズの連戦に読み替えます。**

```
クエスト（＝1セッション）
 ├─ wave 1   形式Aの束（例 スワイプ8問）   敵1体
 ├─ wave 2   形式Bの束（例 消去法4問）     敵1体
 └─ wave 3   形式Cの束（例 文字パネル3問） ★ボス
```

| | |
|---|---|
| 束の組み方 | 既存の `engine.planRun` のまま。**形式は完全な乱数で3つ**（得意不得意で偏らせない） |
| 長さ | 既存のまま 9〜18問（中央値14） |
| 教科 | 既存のまま、くじで3つ出して1つ選ぶ（`engine.drawSubjects`） |
| 学年 | 既存のまま、その教科の埋まっていない一番下（`engine.subjectGrade`） |
| **敵の属性** | **敵ごとに固定。** クエストの教科からは決めない |
| **ボス** | **最後のwaveの敵。** 体力が1.3倍、属性が1体目・2体目と別になるよう選ぶ |
| 挑戦回数 | **無制限**（魔力を入れないため） |

**最後の1問が「いまの範囲の外」であることは変えません**（既存）。**越境問題は
ボスwaveの末尾に置きます。** ボスの最後の一撃が、そのまま「まだ知らない世界」に
なります。

### ハードは入れません

黒ウィズのノーマル／ハードは、**同じ問題を数値だけ変えて2度出す**構造です。
この game の難易度は**学年と段（Lv.1〜3）**がすでに持っています（別の軸なので
混ぜない、という既存の決まり）。**3つ目の難易度軸を作らないでください。**

## 10. 報酬 — 何が変わって、何が変わらないか

**ここが原則3-2の線です。**

| | 速さ | チェイン | 属性相性 | デッキ | 段(Lv) |
|---|---|---|---|---|---|
| **GUM** | 変わらない | 変わらない | 変わらない | 変わらない | 変わらない |
| **知識カード** | 変わらない | 変わらない | 変わらない | 変わらない | 変わらない |
| **クリスタルの抽選** | 変わらない | 変わらない | 変わらない | 変わらない | 変わらない |
| **解説・Tips** | 変わらない | 変わらない | 変わらない | 変わらない | 変わらない |
| **敵に与えるダメージ** | **変わる** | **変わる** | **変わる** | **変わる** | 変わらない |
| **点（score）** | **変わる** | **変わる** | — | — | 変わらない |

**GUMが問題数以外で動くのは1か所だけです** —— **倒しきった束1つにつき +5GUM**
（`engine.battleBonus`）。

**「倒した敵の数」からは GUM を外しました。** 速く答えるほど多くのASが乗るように
なったので、速い人ほど敵を早く倒し、次の敵が湧き、倒した数が増えます。
**そこに GUM を付けると、答える速さがそのまま持ち物の差になります** ——
原則3-2と正面からぶつかります。

**倒しきった束の数は速さで増えません。** 束は3つと決まっていて、敵の体力は
「NICE でその束の8割に正解したら倒れる」ところに置いてあるので、速く答えられない
人も同じだけ倒しきれます。**倒した数のほうは点だけを動かします**（点は買えるものが
何も無く、称号の条件にも入っていないので、持ち物の差になりません）。

経緯は `review-points.md` §21 と §35。

**「自力回答率」「平均回答時間」のような統計を画面に出さないでください**（原則3-2）。
判定（EXCELLENT/GREAT/…）はその場の1回かぎりの表示で、**集計して見せません。**

## 11. ヒーローの入手 — ガチャの代わり

**引くのではなく、解くと仲間になります。** 3つの道があり、**どれも確定です。**

| 道 | 条件 |
|---|---|
| **教科の札** | その教科の知識カードが規定枚数に届くと、その教科に縁のあるヒーローが仲間になる |
| **由来の問い** | その人物そのものの問題を解くと仲間になる（既存の `originCard` と同じ形） |
| **章の解放** | 既存の `engine.unlockedChapters` のまま |

**ショップ（GUM）では買えません。** GUMで買えるのはクリスタルだけです（原則6）。

### どのヒーローを使うか

MCHには404体（うち original 194体）います。**全部は使いません。**

- **`data/roster.json` に、使う分だけを抜いた台帳を持ちます**
- 抜く基準は **`attributes`（MCHが元から持っているタグ）が教科に結び付くこと**。
  `文系学問`（56体）・`理系学問`（45体）・`政治`（52体）・`戦術`・`動物`・
  `三国志`・`戦国`・`イギリス`・`アメリカ大陸` などがそのまま使えます
- **勢力が偏らないように選びます**（original は5勢力に38〜41体ずつ、きれいに散っています）
- 初期ロスターの目安は **5勢力 × 各8体 = 40体**。5枚デッキが組めて、
  属性を選ぶ余地があり、覚えきれる数です

> **「どの40体を選ぶか」は人が決めることです。** MCHの由来と教科の結び付きが
> 納得できるかは機械で判定できません。`review-points.md` に選定の表を出します。

## 12. 育成 — レベルを入れない

**強化合成も進化も限界突破も入れません。**

理由は2つです。

1. **原則1。** 素材を食わせて強くなるなら、強さの源が知識から素材に移ります
2. **進行の数値を2つ持たない**（既存の決まり）。ヒーローのレベルを作ると、
   知識マップと必ず食い違います

**「育った」実感はここから来ます。**

| 動くもの | 何で動くか |
|---|---|
| ヒーローの攻撃力 | **知識カードの網羅率**（§8） |
| 使えるSS | **エクステンションをクラフトして装備する** |
| デッキの自由度 | **知識マップが埋まる → コスト上限が上がる**（§7） |
| 仲間の数 | **解いた教科と、解いた人物**（§11） |

**どれも「解く」ことからしか動きません。** 黒ウィズの育成画面が持っていた
「数字が増える快感」は、**到達度の before/after 表示**（既存・装備画面）が
受け持ちます。
