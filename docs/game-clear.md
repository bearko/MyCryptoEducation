## 1. 作者の決定（#1）

- **クレオパトラ（5016）のチャレンジに勝ったら、ゲームクリア**
- 称号・英雄の解放・知識マップの埋まり具合は、クリアの条件には入れない。**bearko.games のスコアへの加点**にする

## 2. クリアの判定

- `data/heroes.json` のクレオパトラに `"clear": true` を書く。**判定はこの印だけを見ます**（ID を名指しでコードに書かない）
- `engine.gameCleared(db, state)`：印の付いた英雄を手持ちに入れていれば `true`。純粋関数
- `npm run validate`：`clear` の付いた英雄がちょうど 1 体であること、その英雄が一番奥の章を開く（`unlocks` が全英雄の中で最大）ことを見る
- クリアした日を `S.clearedAt`（`"YYYY-MM-DD"`）に 1 回だけ記録する。記録からの再挑戦は無いので、二度書かれることはない

### クリアしても変わらないもの

**ゲーム内の報酬は 1 つも足しません。** GUM・知識カード・クリスタル・称号は、いまのチャレンジに勝ったときと同じです（原則2・原則3-2・原則7）。クリアは「ここまで来た」という記録で、手に入るのは次の問い（クレオパトラが開く世界の12歳の問題）だけです。

**クリアのあとも遊び続けられます。** 問題 DB は増え続けるので、ゲームを閉じる画面は作りません。

### 画面

- チャレンジの結果（S-19 の勝った側）に 1 行足す：「ゲームクリア ・ 世界の教室の、いちばん奥の扉が開きました」。ほかの「＋」の行と同じ形
- マイページ（S-24）の名前の下に「ゲームクリア ・ 2026-10-17」を出す。クリアしていなければ何も出さない（「未クリア」とは書かない。原則3）

## 3. bearko.games に送る成績

`src/platform.js` の `platformMetrics(S)` が作る。**答え方（難モードか4択か、ヒントの本数、速さ）は入れません**（原則3-2）。ゲーム内の点 `S.score` も入れません（CLAUDE.md「点だけは例外です」——点を称号やほかの数字につなげない）。

| 送る成績 | 中身 |
|---|---|
| `cards` | 知識カードの枚数（いまと同じ） |
| `cleared` | クリアしたか（`gameCleared`） |
| `heroes` | チャレンジで解放した英雄の数（`rel` を持つ英雄のうち手持ち。最初からいる MCH の3体は数えない） |
| `titles` | 取った称号の数（`earnedTitles`） |
| `cells` | 知識マップの埋まったマスの数（知識マップの画面の「◯ / 48マス」と同じ数え方） |

- 送るのは、どれかが増えたときだけ。1 分に 1 回まで（いまと同じ）。**クリアした瞬間だけは待たずに送り、通知を出す**（自己ベストの通知。積み上げなので、ほかは通知を出さない）
- 計算式は共通基盤（MyCryptoPortfolio の `platform/scoring/education.v2.js`、SPEC-002 3.6）。係数は暫定：

```
点 = （クリアしていれば 5,000）＋ 知識カード × 6 ＋ 埋まったマス × 30 ＋ 解放した英雄 × 150 ＋ 称号 × 150
```

| 例 | 点 |
|---|---|
| 遊び始め（カード 47・マス 12・英雄 1・称号 1） | 約 940 |
| ふつうのクリア（カード 469・マス 40・英雄 6・称号 4） | 約 10,500 |

- 知識カードには上限が無い（問題が増えれば伸びる。SPEC-002 の D11）。マス・英雄・称号は数に限りがあるが、それぞれは加点の一部なので頭打ちにはならない

## 4. RTA の区切り

**章はクリアの道順になっていません。** クレオパトラにはいつでも挑めるので、第3章（エジソン）を開かずにクリアできます。そこで、どんな順に解いても必ず通る 2 つで区切ります。

| 順 | ID | 種類 | 中身 |
|---|---|---|---|
| 1 | `hero1` | stage | 最初の英雄をチャレンジで解放した |
| 2 | `clear` | clear | クレオパトラに勝った（ゲームクリア） |

- 1 回の勝ちで両方に届いたとき（最初の挑戦でクレオパトラに勝った）は、`hero1` → `clear` の順に続けて送る
- 区切りに届いたかは純粋関数 `engine.checkpointsReached(db, before, after)` で決め、送るのは `platform.js` の `platformCheckpoint(id)` **1 か所だけ**
- いまは RTA の計測を始める入口がありません（進行を端末に保存しているので、RTA には「最初から」の入口が要る）。**`platformCheckpoint` は、計測中（`BearkoGames.rta.current()` が Education のレギュレーション）のときだけ送り、それ以外は何もしません。** 入口とレギュレーションの登録は、あとで別に作る

- **ゲーム内の報酬は 1 つも足しません。** アチーブメントは bearko.games のマイページに並ぶ記録で、GUM・知識カード・クリスタル・称号は変わりません（原則3-2・原則7）。条件はどれもセーブに残る持ち物と積み上げの数で、**答え方・速さ・正答率・連続ログインでは変わりません**
- どれを満たしているかは純粋関数 `platformTrophies(db, S)`（`src/platform.js`）。送るのは `platformSyncTrophies` **1 か所だけ**で、`notePlatformProgress`（保存のたび）から呼ぶ
- このページを開いてからまだ送っていないものだけを、**1 つずつ順に**送る（未ログインで同時に送ると、Cookie がまだないので仮アカウントが送った数だけできてしまう）。サーバーは同じものを二度数えない
- 開いた時点ですでに満たしているもの（アチーブメントが入る前から遊んでいた人）も、最初の描画で送られる。通知は SDK が出す（はじめて取ったときだけ）
- 共通基盤がまだ知らない ID は、公開まで共通基盤がはじくだけで、遊びには影響しない
- SDK が読めない・通信に失敗しても何もしない

## 6. 検査

- smoke：クレオパトラに勝つとクリアになる・ほかの英雄ではならない、クリアの分だけ増える GUM・知識カード・クリスタルが無い（ふつうのチャレンジの勝ちと同じ）、送る成績の形、`checkpointsReached` の順番
- validate：`clear` の印がちょうど 1 体、一番奥の章を開く英雄に付いている
- smoke：`platformTrophies` の条件（ゲームが送る 14 個すべて）、同じアチーブメントを二度送らないこと、順に送ること
