# 写真を取り込んで push するまで

**分担がはっきりしています。探すのは Claude、運ぶのはあなたです。**

| | できること | できないこと |
|---|---|---|
| Claude | **コモンズを検索して File 名を決める**（`WebSearch` は通る） | 画像を取ってくること。`commons.wikimedia.org` は組織のポリシーで **403**（proxy に記録が残る）。`WebFetch` も同じ |
| あなた | ネットに出て取ってくること。**写っているものを目で見ること** | — |

だから**ふだんの手順はこれだけ**です。台帳の `commons` にはもう File 名が入っているので、
探す作業はありません。

```powershell
git pull
node scripts/fetch-commons.mjs     # 名指しされた1枚を採るだけ
npm run validate
```

そのあと `public/commons/` の webp を開いて、**狙ったものが写っているか確かめてから**送ります。

```powershell
git add -A
git commit -m "◯◯の写真を取り込む"
git push
```

**ライセンスの取り違えは機械が止めます。** `data/images.json` の `allow` に無いものは
`fetch-commons.mjs` が採りませんし、`titleFree: true` の行に CC BY が来たら
`npm run validate` がエラーにします。**止まらないのは「写っているものが違う」だけ**で、
そこが人の目の出番です。

## File 名が入っていないとき

台帳の `commons` が空の行は、Claude がまだ File 名を決めていないぶんです。
**「◯◯の写真がほしい」と言ってください。** こちらで検索して File 名を書き込みます。

自分で選びたいときは、候補を写真のまま並べる画面があります。

```powershell
npm run pick:commons
```

`http://127.0.0.1:3100/` が開くので、よさそうな1枚を押すだけです。押した時点で webp が
書かれ、題名・作者・ライセンス・出典も台帳に埋まります。

---

## `npm run pick:commons` が何をするか

台帳（`data/images.json`）のうち、**まだ写真の無い行**をぜんぶ集めて、
候補を写真のまま並べた画面を `http://127.0.0.1:3100/` に出します。
1枚押すと、その場で webp が書かれ、台帳の欄（題名・作者・ライセンス・出典）も
埋まります。**終わったら画面の「終わる」を押してください。**

行を名指しすることもできます。

```powershell
npm run pick:commons -- obj-pan obj-inu
```

画面の見かたは3つの印だけです。

| 印 | 意味 |
|---|---|
| `◎` | PD・CC0。**題名を伏せられる**ので、スワイプと絵の選択肢はここからだけ選びます |
| `○` | 使えるが、題名の表示が要るもの（CC BY）。解説に添える写真なら構いません |
| `×` | `allow` に無いライセンス（CC BY-SA・NC・ND） |

**使えない候補も、理由を付けて灰色で並びます。** 消してしまうと、
「なぜ1枚も採れなかったのか」が画面から読めず、検索語の直しようがないためです。

**なぜ画面にしたか。** これまでは3往復かかっていました——検索語を書く →
`--list` の出力を読む → `commons` に File:名 を書く → 採る。しかも文字だけなので、
**写っているものが適切かは結局あとで見ることになります。** 実際に、婚礼の写真・
顔だけの接写・カフェにいる人・マヨネーズの皿が来ました。

---

## 台帳に何を書くか

**写真を探す手がかりは4種類あり、この順に見ます。** 上のものほどよく当たります。

| 欄 | 書くもの | どこから引くか |
|---|---|---|
| `commons` | `File:〜.jpg` | その1枚を名指し。検索を飛ばす |
| `entity` | 日本語の語（`"食パン"`） | ウィキデータの項目 → P18「画像」 |
| `wikipedia` | 記事名（`"イヌ"` / `"en:Bread"`） | その記事の先頭に出ている画像 |
| `category` | コモンズのカテゴリ名 | その中のファイル |
| `search` | 英語の検索語 | 全文検索（**最後の保険**） |

```json
"obj-pan": { "entity": "食パン", "wikipedia": "食パン",
             "alt": "パンがひとかたまり、そのまま置かれている写真", "titleFree": true }
```

**まず `entity` を書いてください。** ウィキデータの P18 と記事の代表画像は、
**人が「これがその物の画像だ」と決めたもの**です。全文検索はファイル解説ページの
全文が対象なので、投稿者名やカテゴリの文言にも当たります。実際に起きたこと：

- `dog sitting portrait` → 投稿者名 `DogTwo` に当たり、**カフェにいる人の写真**
- `chicken egg white` → **マヨネーズの皿**（卵は脇に写っているだけ）
- `Shakespeare Chandos portrait` → **ヘンデルの肖像画**（同名の絵が別人にもあった）

**「Xの写真がほしい」に対して、全文検索はそもそも道具が違いました。**

`titleFree: true` は「この写真は被写体の名前を伏せたまま出す」という印です
（スワイプと絵の選択肢）。この印がある行は、取り込みのほうが CC BY を採りません。

## 取り込みが当たらないとき

### 候補がゼロのとき

**絞りこみのかけすぎです。** `insource` と長い検索語を重ねると、条件を全部満たす
ファイルが無くなります。画面にも「引けなかった源」が出ます。

`entity` を書けばたいてい解決します。それでも出ないときは、検索語を2〜3語に
短くしてください。

### 端末だけで済ませたいとき

```powershell
node scripts/fetch-commons.mjs --list obj-pan
```

取り込まずに候補を20件並べます。印は画面と同じ（`◎` / `○` / `×`）で、
どの源から来た候補かも出ます。

```
  obj-pan
   ◎  1. Public domain      1024x768   ウィキデータ Q7802  File:Bread rolls.jpg
   ○  2. CC BY 2.0          1024x768   全文検索           File:No-Knead Bread.jpg
   ×  3. CC BY-SA 2.0       2048x1536  全文検索           File:Sliced banana bread.jpg
      ※ この行は題名を伏せる用（titleFree）です。◎ からだけ選んでください
```

### 1枚を決め打ちする

候補から選んだら、`data/images.json` のその行に書きます。

```json
"obj-pan": { "commons": "File:〜.jpg", "alt": "…" }
```

`commons` があると、ほかの手がかりを飛ばしてその1枚を採ります。
**画面で押した場合も、内部でこれと同じことをしています。**

## 採れた画像は、必ず目で見てください

**ライセンスは機械が保証できますが、写っているものが誰か・何かは保証できません。**
`public/commons/` の webp を開いて確かめます。見るところは3つ。

1. **狙った被写体か。** 上に挙げたとおり、別人・別物がふつうに来ます
2. **画中に名前が書かれていないか。** 切手や版画には名前が刷りこまれていることが
   あります（ガウスの切手、芭蕉の版画）。スワイプで「名前を伏せる」狙いが崩れます
3. **小さくしても分かるか。** 絵の選択肢は 88px 幅です。遠景の風景や、
   皿や袋に隠れたものは、この大きさでは読めません

## push が通らないとき

### `local changes would be overwritten`

```powershell
git diff data/images.json
```

**何も出ないなら、中身は同じで改行コードだけの違いです。** 捨てて構いません。

```powershell
git checkout -- data/images.json
git pull
```

`.gitattributes` を入れてあるので、いまは起きにくくなっています。まだ出るようなら
一度だけ `git add --renormalize .` を走らせてください。

### `non-fast-forward` / `tip of your current branch is behind`

**GitHub のほうが進んでいます。** そのまま `git pull` を重ねると
`data/images.json` で衝突することがあります（同じ行を両方から触るため）。

コミットをすでに作ってしまっているなら、**main を触らずに別の枝として送ってください。**

```powershell
git push origin main:refs/heads/bearko-photos
```

こちらで中身を見て取り込み、main へ入れます。そのあと手元をそろえ直します。

```powershell
git fetch origin
git reset --hard origin/main
```

## 取り込みの決まり（`CLAUDE.md` から）

- 使えるライセンスは **PD・CC0・CC BY** だけ（`data/images.json` の `allow`）。
  **CC BY-SA・NC・ND は使いません**
- **写真はクレジットとセットでしか出しません。** 作者・ライセンス・出典を必ず表示します
- **スワイプと絵の選択肢（`choiceArt`）の写真は PD・CC0 に限ります。** この2つだけ、
  出題中に題名を伏せられます（題名が被写体の名前そのものなので、出すと答えになります）。
  台帳のその行に `"titleFree": true` と書いておくと、**取り込みのほうが CC BY を採りません**
- **画中に名前が刷りこまれていても、答えにならなければ構いません。** ガウスの切手には
  `C.F.GAUSS` と入っていますが、問うているのは正十七角形や足し方なので漏れません。
  **むしろ「この人」が誰か分かるぶん、問いが成立します。** 伏せたいのは
  スワイプの被写体そのものを当てさせる問いのときだけです
- **`alt` は問題ごとに書きます。** 台帳の `alt` は被写体を名指ししているので、
  そのまま出すと答えになります
- CI では走らせません（相手先のサーバに負荷をかけないため）。1件ごとに1.2秒待ちます

## 問題DBの拡張 — 写真から先に進める（第1便）

**目標は 教科×学年 で100問、うち画像つき20問です。** 実在するマスは48。
小学校だけで 国語6・算数6・理科4・社会4・外国語4 = **24マス**あります。

**写真は480枚も要りません。** 1枚が何マスにも効くからです。

| 写真の束 | 効くマス |
|---|---|
| **身の回りのもの51枚**（動物・食べ物・道具・乗り物・自然） | 国語のかな／カタカナ／漢字／数え方（小1〜小4）・算数の数える／単位（小1〜小2）・外国語の単語（小3〜小6） |
| **理科16枚**（こん虫・植物・器具・地層・空） | 理科 小3〜小6 |
| **社会14枚**（はたらく車・田んぼ・建物・出土品） | 社会 小3〜小6 |

**第1便は81枚です**（台帳は114行になりました）。**51枚は `titleFree: true`** ——
絵の選択肢（`choiceArt`）とスワイプに使うので、題名を伏せられる **PD・CC0 からしか
採りません**。残る30枚は「この虫の〜」と写真を指して問うので、CC BY でも構いません。

### 手順（人が走らせるところ）

```bash
node scripts/fetch-commons.mjs        # 台帳の空いている行だけを採りにいく
npm run validate                      # 採れたか・ライセンスが合っているかを見る
git add data/images.json public/commons && git commit && git push
```

**全部は採れません。** `titleFree` の行は PD・CC0 だけなので、日用品のように
CC BY-SA が多い被写体では空振りします。**空振りした行はそのまま残るので、
次の便でキーを変えるか、`commons` に File 名を書き足してください。**
`node scripts/fetch-commons.mjs --list <キー>` で候補を並べられます。

### そのあと（Claude 側）

採れた写真を見て、**A（写真を読む）か B（写真で指す）のどちらかになる問題**を
書きます。**C（飾り）は作りません。** 採れた枚数が分かってからでないと、
存在しない写真を指す問題を書いてしまうので、**問題を書くのは取り込みのあと**です。

### 便の見通し

| 便 | 中身 | 枚数 |
|---|---|---|
| 第1便 | 身の回りのもの・理科小3〜6・社会小3〜6 | **81**（済） |
| 第2便 | 国語（漢字の成り立ち・故事成語）・算数（図形・単位） | 約70 |
| 第3便 | 外国語（場面・国と文化）・社会（地理・歴史の人物） | 約70 |
| 第4便 | 中学校（理科の器具・社会の資料・情報） | 約70 |

**図形（SVG）とテキストの問題は、写真を待たずに並行して足せます。**
図形は `data/figures.json` に手で書くので、ネットワークが要りません。

### 第1便の結果 — 81枚のうち、使えたのは28枚でした

**取り込みそのものは54枚成功しました。** ただし**目で見たら、半分は別のものが写っていました。**

| 台帳のキー | 来たもの |
|---|---|
| `obj-kasa`（傘） | **散形花序の図**（植物用語の「傘」） |
| `obj-hasami`（はさみ） | **シオマネキ**（カニのはさみ） |
| `obj-gitaa`（ギター） | **バガヴァッド・ギーターの写本** |
| `obj-kumo`（雲） | **アリストパネスの喜劇『雲』の木版画** |
| `obj-umi`（海） | **ドビュッシー『海』の楽譜表紙** |
| `obj-zou`（象） | **ソウルオリンピックの聖火台** |
| `obj-hikouki`（飛行機） | **旅客機の衝突実験の火の玉** ← 子ども向けの画面に出せません |
| `obj-gyuunyuu`（牛乳） | **乳糖の構造式** |
| `shakai-fujisan`（富士山） | **幕府の軍艦「富士山丸」** |

**原因は、日本語の語がウィキデータで別の概念に解決されることです。**
同じ字を使う別のものが、その項目の代表画像になっていました。

**`entity`（日本語）より `wikipedia: "en:..."` のほうが、物としては一意に決まります。**
英語版の記事名は物ごとに分かれていて（Umbrella / Scissors / Cloud）、その先頭画像は
「これがその物の代表だ」と人が決めたものです。**採り直しの26行は、この形に
書き換えてあります**（`category` も併記して二の矢にしてあります）。

**ライセンスは機械が止めましたが、「写っているものが違う」は止まりません。**
そこは目で見るしかありません——採ったあとに `public/commons/` を並べて見る手も
あります（縮小して1枚に並べると、12枚ずつまとめて確かめられます）。
