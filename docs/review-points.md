## 2. 由来の文章（`origin`）の断定度

`data/extensions-curated.json` の108件を、断定の度合いで分けました。
**いまはクラフト画面の説明文としてそのまま出ています。**

- ぼかし語あり（と伝わる／とされる／諸説）… 16件
- 作品名・神話と明示（『三国志演義』『オデュッセイア』など）… 30件 ← **そのままで問題なし**
- 断定 … 62件

断定62件のうち、**確認したほうがよいと思うものだけ**を挙げます。残り50件は史実として
問題ないと判断しました。

### 事実として疑わしいもの

- [ ] **`4042` エアログラファイト**「密度は空気の数倍程度」
      → **向きが逆ではないでしょうか。**エアログラファイトは空気より軽い素材として
      知られているはずです。数値をあたって直したほうがよさそうです
- [ ] **`5047` ビクトリア号**「地球が球体であることを実証した」
      → 球体であること自体は古代から知られていました。周航が示したのは
      「一周して戻れる」ことのほうです。このままだと誤解を招きます

### 伝説・逸話を史実として書いているもの

- [ ] **`5005` ブケファロス**「少年期に彼だけが乗りこなした」← プルタルコスの伝える逸話
- [ ] **`5032` 白羽根太極**「諸葛亮の羽扇」← 羽扇は後世の造形で、史実の裏付けは弱い
- [ ] **`5179` トロイの木馬**「トロイア戦争でギリシャ軍が用いた計略」
      ← トロイア戦争そのものが叙事詩の世界。「神話」「叙事詩」の語がありません
- [ ] **`5127` 雛人形**「平安の流し雛に起源をもつ」← 起源には諸説

### 通説を断定しているもの（軽い）

- [ ] **`5028` フランベルジェ**「炎を意味する語に由来する」← 語源に諸説
- [ ] **`4016` 兵法書**「中国最古の兵法書」← 「最古」の断定
- [ ] **`4107` アタナソフ**「世界初の電子式デジタル計算機を設計した」
      ← ENIAC との優先権に係争があった経緯があります
- [ ] **`5506` 三日月宗近**「刃文の打除が三日月に見えることから」← 名の由来は通説

## 3. 勝手に決めた設計判断

確認を取らずに決めたところです。**違うと思ったら言ってください。**

- [ ] **黒曜石と石綿を、生物起源から鉱石に移した。**
      実装計画 §2-1 の表では生物起源でしたが、黒曜石は溶岩のガラス、石綿は珪酸塩鉱物で、
      どちらも生き物に由来しません。族は図鑑の見出しとして画面に出るので、
      そこに誤りを置かないほうを取りました。結果として生物起源は3種です
- [ ] **情報に鉱石を割り当てた。** 旧い表では理科に元素と鉱石の2つが付き、情報には
      何も付いていませんでした。1対1でないと、解いても貯まらない族と2倍貯まる教科が
      できるので、鉱石を情報へ回しました（磁鉄鉱の磁気記録、雲母の絶縁）
- [ ] **GUM を教科ごとに変える案は入れなかった。** 出にくさは当たりの大きさで
      すでに補われていて、そこに GUM を足すと揃えたはずの期待値が崩れます。
      GUM は学年の梯子のままです（原則6を触らずに済みました）
- [ ] **クラフトが鉱物を消費するのをやめた。** 鉱物は手に入れた時点でポイントに変わり、
      図鑑には残り続けます。消費させると、たまに出た高い鉱物が安いレシピに丸ごと
      食われますし、クラフトのたびに図鑑が欠けて豆知識が読めなくなります
- [ ] **Common に相当する品にも素材を要求するようにした。** 魔石を抜くと入口の関門が
      消えて、素材なしで作れてしまうためです
- [ ] **`below`（下位を1つ食う）の階段を無くした。** 由来のある108種には
      下位・上位の連なりが無いためです。階段は知識の広がり（初伝→中伝→奥伝）が担います
- [ ] **旧40種のエクステンションを引退させた。** 引き継ぎ書には「併存させ、どちらを使うかは
      実装時に決める」とありましたが、2つのクラフト体系が並ぶことになるので、
      curated 側に寄せました。画像27点も消しています

## 6. 消去法を「何個まで削るか」の駆け引きにした

**いちばん見てほしいところです。** 一度「絞り込み」（2つ消す→残り2つから選ぶ）を
入れましたが、段階で押す意味が変わるのが分かりにくく、二段に分ける面白さも薄かったので、
作り直しました。

```
✕ で1つ消す → その場で当たり外れが決まる → 点が入る → もう1つ消すか、ここでやめるか
1つ目 ＋2 ／ 2つ目 ＋3 ／ 3つ目 ＋5   （3つ消しきれば正解確定で、さらに基礎点）
```

- [ ] **点の刻み（2 / 3 / 5）。** リスクに比例しているか。全部削れば＋10で、
      基礎点10と合わせて20点。4択に降りて正解すれば10点です。**倍の差は大きすぎないか**
- [ ] **外したときに「消せたぶんは残る」ことが伝わるか。** 正解を消すとその場で終わりますが、
      それまでに入った点は取り返されません。画面では点が減らないことでしか示していません
- [ ] ✕ は 46×46px 以上にしてあります。指で押せる大きさか（実機で確認をお願いします）
- [ ] 消した行は打ち消し線で薄く残します。＋2 が浮き上がって消える演出を入れました

### 「3つ消す」と「1つ選ぶ」を同居させないことにした ← 直近の変更

一度は ✕（消す）と文字（答える）を左右に分け、削らずそのまま答えられるようにしていました。
**逆に混乱を招くという指摘を受けて、消去法では文字を押せなくしました。** いまこの画面で
できるのは ✕ で消すことだけです。

- [ ] 選択肢の文字はただの文字に見えるか。**押せそうに見えていないか**
      （ボタンではなく `div` にし、hover で枠色が変わらないようにしてあります）
- [ ] 帯の文言を「誤っているものを 3つ 消す」に戻しました。**これで迷わないか**
- [ ] **「4択に切り替える」を戻しました。** 文字が押せない以上、正しいものを1つ選びたい人の
      逃げ道はここだけです。選択肢の下に置いてあります。**気づける位置か**
- [ ] 難易度のつまみが2段になりました。**何個まで削るか**と、**そもそも削るのをやめて
      4択へ降りるか**です。段が増えすぎていないか

### 増やすのは点だけ ← 決定済み

**GUM・クリスタル・知識カードは動かしません。** 原則3-2 にその線引きを書き足しました。

根拠は「残高になるかどうか」です。点は買えるものが何も無く、称号の条件にも入っていません
（`S.score` は画面に出るだけで、どこからも参照されていないことを確かめてあります）。
だから深く踏みこんだ人とそうしない人のあいだに、持ち物の差が残りません。

**点を何かに使えるようにすると、この例外は成立しなくなります。** 買い物にも称号にも
つなげないでください。つなげるなら、削った数による加点のほうを先に外すことになります。

## 27. 写真が21件すべて見送りになった件 ← 新規

**取り込みを走らせると、残り21行がすべて「候補がありません／使える候補がありません」に
なりました。** 出力を読むと原因は**ライセンスではなく、候補の集め方**でした。

### 27-1. 何が起きていたか

| | 中身 |
|---|---|
| **① カテゴリの直下が空** | 大きなカテゴリは中身がほとんど下位カテゴリです。`Category:Ships` の直下にファイルはほぼ無く、`categorymembers` が空を返していました。「見えたもの: 」が空だった行はこれです |
| **② 転送カテゴリ** | `Category:Equus caballus` は `Category:Horses` への転送で、メンバーを持ちません |
| **③ 写真以外が混ざる** | `gcmtype: "file"` は名前空間6のことなので、音声も動画も PDF も入ります。雲のカテゴリから解説音声（`De-Cumuluswolke.ogg`）が、鶏のカテゴリから `Ryujin.tif` が来ていました |
| **④ 集めてから落としていた** | コモンズの写真の多くは CC BY-SA です。候補が1〜6件しかないところへライセンスの網をかければ、**必ず全滅します** |

### 27-2. 直したこと

- **`deepcategory:` で下位カテゴリまでたどる**ようにしました（①②）
- **写真だけに絞る**（`filetype:bitmap` ＋ 拡張子）（③）
- **ライセンスを、集めてからではなく探すときに絞る**（④）。構造化データの
  `P6216=Q19652`（パブリックドメイン）と `P275=Q6938433`（CC0）で先に引き、
  そのあとライセンス無指定の段も足します。**無指定の段を残したのは、構造化データが
  付いていない写真を落とさないためです**（Q番号が違っていても、ここで拾えます）
- **`titleFree` の行には無指定の段を足しません。** PD・CC0 しか使えないので、
  足すと画面が × で埋まります
- **転送カテゴリらしい6行を付け替え、21行すべてに `search`（英語）を足しました。**
  カテゴリ名が違っていても候補がゼロにならないようにするためです

### 原則3-2のために、既存の仕様をひとつ戻しました ★

**倒した敵1体につき +3GUM を外しました**（`engine.KILL_GUM` = 0）。

黒ウィズ型にしたことで、**速く答えるほど多くのASが乗る**ようになりました
（EXCELLENT 5体 / NICE 2体）。速い人ほど敵を早く倒し、次の敵が湧き、**倒した数が
増えます。** そこに GUM が付いていると、**答える速さがそのまま持ち物の差**に
なります —— 原則3-2（報酬をプレイスタイルで差別化しない）と正面からぶつかります。

**倒しきった束の数（+5GUM）は残しました。** 束は3つと決まっていて、敵の体力は
「NICE でその束の8割に正解したら倒れる」ところに置いてあるので、**速く答えられない
人も同じだけ倒しきれます。** 速さでは増えません。

**倒した数が動かすのは点だけになりました**（+20点）。点は買えるものが何も無く、
称号の条件にも入っていないので、持ち物の差になりません。

**§21 で確認済みだった仕様を、確認を取らずに戻しています。** 戻すほうが原則に
沿うと判断しましたが、**元に戻したいときは `engine.KILL_GUM` を 3 にするだけです。**

### いまの穴（次の段で埋めるところ）

- **スワイプの束ではSSが撃てません。** スワイプの画面にはデッキ行を置いていない
  ためです（バトルの層そのものが元から出ていません）。ゲージは溜まるので、
  次の束で撃てます。**8問続くので、ここは気になるかもしれません**
- **接敵の画面（S-29）に持ち時間を出していません。** 仕様では「行く前に見せる」と
  書いてあります。いまは「出題を選ぶ」の札に出しています
- **ボスの体力の上乗せ**（`BOSS_HP` = 1.3）は、全問正解ぶんの頭打ちに丸められて
  効かないことがあります

### 機械が守っているところ

**「速く答えたら得をする」実装がうっかり入っても止まります**（原則3-2）。

```
✓ 速さを変えても GUM・知識カード・クリスタルが1つも動かない
✓ 速さで変わるのは敵に与えるダメージのほう
```

ほかに smoke へ27項目（相剋の輪・判定とAS本数・チェイン半減・コスト超過25%ダウン・
SSのゲージ・時間切れでも知識カードは入る・ヒントを開くと時計が止まる・
仲間の増え方に抽選が無い）、validate へ属性とロスターと持ち時間の検査、
touch-check へ12項目（持ち時間バー・デッキ5枠・チェインの位置・SSのポップアップ）を
足しました。

## 36. ヒーローと敵を大きくして、画面を4つの帯に組み直しました ← 新規

**2つの指示をまとめて入れています。**

1. 「全体的にヒーローやエネミーを大きく表示してほしい」
2. 「バトルエリアと出題エリア、回答エリアの比率は添付（黒ウィズの実画面）を参考に」

### 比率

添付の3枚を測ると **バトル 37% / 設問 18% / 解答 40% / フッター 5%** でした。
ここは次のようにしています。

| 帯 | 黒ウィズ | ここ |
|---|---|---|
| バトル | 37% | **32%** |
| 設問 | 18% | **18%** |
| 解答 | 40% | **38%** |
| デッキ行 | 5%（戻る／▶▶▶） | **10%** |

**バトルが 5pt 小さいのは、デッキ行があるからです。** 黒ウィズは出題中に精霊を
出しません（攻撃の演出のときだけ出ます）。ここは**5枚の並び順がそのままルール**
なので、答えているあいだも見えているほうがよいと判断しました。
**ここは勝手に決めた線です** —— デッキ行を畳んでバトルを 37% にすることもできます。

### 大きさ

**原本は 64x64 なので、64 の整数倍で出しています**（半端な倍率だと、1ドットが
1px のところと 2px のところができて輪郭がガタつきます）。

| どこ | 前 | いま |
|---|---|---|
| 出題中の敵 | 56px | **192px**（詰めた帯では128px） |
