# 体験デザインのフレームワーク

玉樹真一郎『「ついやってしまう」体験のつくりかた 人を動かす「直感・驚き・物語」のしくみ』（ダイヤモンド社, 2019）をゲームサイクル設計の土台にします。

**このファイルは書籍の要約ではありません。** 公開情報で確認できた枠組みと、それを本プロジェクトに当てたときに見えた論点を記録するものです。細部を詰めるときは書籍を参照してください。

---

## 三層の構造

| 層 | サイクル | 役割 |
|---|---|---|
| **直感のデザイン** | 仮説 → 試行 → 歓喜 | シンプルで簡単な体験で「直感」させる。人々の共通点（脳と心の性質／共通の記憶）を利用する |
| **驚きのデザイン** | 誤解 → 試行 → 驚愕 | 予想が外れる驚きで疲れや飽きを払拭する。人々の思い込み（前提への思い込み／日常への思い込み）を利用する |
| **物語のデザイン** | 翻弄 → 成長 → 意志 | 体験を通してユーザ自身の物語を生み出させる |

**組み立て方**：直感のデザインを連続させつつ、疲れや飽きに応じて驚きのデザインを挿入する。

```
① ① ① ① ① ② ① ① ① ② ① → … → ①
```

物語のデザインは、その連なりの上に被せる層です。物語の終わりにプレイヤーをスタート地点に戻すことで、体験を通り抜ける前後の自分を比べさせ、成長を実感させます。

終章の結論は「体験 → 感情 → 記憶」。体験が感情を生み、感情が記憶に残る。この流れが人を突き動かす、という整理です。

## 10種のタブーのモチーフ（驚きのデザインの弾）

日常への思い込みを破るために使うモチーフ。書籍では「〜感」という形で説明されています。

| モチーフ | 感じ |
|---|---|
| 性 | ときめく感じ、エッチな感じ |
| 食 | 美味しそう感、腹減った感 |
| 損得 | お金欲しい感、損したくない感 |
| 承認 | 認められた感、所属している感 |
| けがれ | 汚い感、罪悪感 |
| 暴力 | 痛い感、一方的感 |
| 混乱 | まちがってる感、クラクラ感 |
| 死 | 死に近づく感、オカルト感 |
| 射幸心と偶然 | 賭けている感、祈っている感 |
| プライベート | 恥ずかしい感、秘密感 |

## 成長のモチーフ（物語のデザイン）

| モチーフ | 内容 |
|---|---|
| 環境ストーリーテリング | 環境の中に配置された断片的な情報を、ユーザーが自発的に集めながら物語を構築していく |
| テンポとコントラスト | シーンに含まれる情報量と、受動的／能動的の配分をコントロールする |
| **収集と反復** | 集めさせ、繰り返させる。**同時に難易度調整の機能を持つ**（下記） |
| **選択と裁量** | リスクとリターン → 選択と裁量 → 成長。**同じく難易度調整の機能を持つ**（下記） |
| 翻意と共感 | 苛立たせるよう設計された同行者を通じ、憎しみから共感へとユーザーを成長させる |

### 成長のモチーフが難易度調整装置でもある、という要点

書籍の中核はここでした。**収集と反復も、選択と裁量も、プレイヤー自身に難易度を調整させる仕組みとして働きます。**

- **収集と反復** — ある収集対象がどうしても手に入らないなら、もっと簡単に手に入る別のものを集めればよい、という抜け道がある。この逃げ道が難易度のつまみになっている
- **選択と裁量** — スーパーマリオのBダッシュが典型。難しい場面では歩けばよく、Bダッシュするかしないかを裁量することで、プレイヤーはゲームの難易度そのものを裁量している

同じことを反復させられ、迷わされてもプレイヤーがやめないのは、**プレイヤーが自分の感覚で難易度を調整し、自分の力量に合った選択をして、できる限りの努力をしてくれる**からです。だからゲームは、無数のプレイヤーそれぞれにとってちょうどよい難しさで遊ばれる。**プレイヤーによる難易度調整は、成長に欠かせない要素**だと位置づけられています。

### 「失敗はお前のせいだ」

もうひとつ、報酬設計に直結する原則があります。**ゲームはプレイヤーに、失敗が自分の責任だと感じさせなければならない。**

明確な失敗をしたとき、それを架空の物語上の他人事ではなく自分事として捉えてもらえるかどうかが重要になります。調子に乗ってBダッシュしっぱなしで最弱の敵にやられ、プレイヤーが「俺のせいだ」と自分を責める——あの構造です。

**本プロジェクトでは、この原則と「不正解が罰にならない」を両立させます。** 矛盾しません。

> **失敗は自分のものだが、罰されない。**

そのために、プレイヤーに難易度のつまみを渡します。つまみを自分で回した結果の失敗は、選択肢が紛らわしかったからではなく、自分の判断の結果になります。

## ⚠ 確認できていない箇所

次の用語は書籍の図には登場しますが、**正確な定義まで確認できていません。** 論点になったら書籍で裏を取ってください。推測で進めないこと。

- 命のやりとり
- 未知の体験（目次の「成長の果てでなければたどりつけない体験」に対応すると思われる）
- 解釈の余地
- 伏線（「ある情報の真意がわからない状態で提示し、時間差で真意に気づかせる」という説明が二次情報にあるが未確認）

**解決済み**：収集と反復、選択と裁量、および「失敗はお前のせいだ」の原則は、書籍の該当ページを直接確認して上記に反映しました（2026年9月）。

なお、二次情報由来の記述は著者の意図と微妙にずれている可能性が残ります。

## 本プロジェクトに当てたときの2つの論点

### 論点1：いちばん強い驚きの弾が、コンセプトガードで封じられている

10タブーのうち**「射幸心と偶然」と「損得」は、本プロジェクトでは使えません。** `CLAUDE.md` の原則2（ランダム報酬を入れない）で明示的に排除したものだからです。

これは矛盾ではなく、**どのタブーで代替するかという設計課題**として扱います。

**「混乱（まちがってる感、クラクラ感）」が本命です。** 第3章の壁（習っていない単元）と第4章の壁（同い年の海外の問題）は、まさに前提への思い込みを外す仕掛けとして機能しています。学年は下がるのに解けなくなる、という体験が「クラクラ感」そのものです。

副次的に使える弾：

- **承認** — 称号。ただし「越境」に対して出すこと（`docs/design-decisions.md` 参照）
- **プライベート（秘密感）** — 知識マップの空白は、他人には見せたくない自分の弱点そのもの
- **食・けがれ・死** — 問題の題材としては使える（クリスタルの毒性、歴史上の疫病など）が、報酬設計には持ち込まない

### 論点2：物語のデザインの「意志」が丸ごと欠けている

物語のデザインは 翻弄 → 成長 → **意志** の3段です。現行の5段階設計を当てるとこうなります。

| 書籍 | 本プロジェクトの現状 |
|---|---|
| 翻弄 | ✅ 第3章の新課程、第4章の海外問題 |
| 成長 | ✅ 知識マップ、復習ラウンド、英雄の解放 |
| **意志** | ❌ **該当なし** |

「意志」は、**プレイヤー自身の意志で運命を切り開かせる**段階です。いまのゲームには、プレイヤーが自分で決めて、その決定が物語を変える、という契機がありません。出題範囲を選べますが、それは効率の選択であって意志ではない。

**ゲームサイクルを本格設計するなら、ここが最大の空白です。** 候補としては、

- 「どの英雄を次に解放するか」を自分で選び、選んだ相手によってその後の出題傾向が変わる
- 知識マップの空白を「あえて残す」選択（全部埋めることが正解ではない設計）
- 自分の得意分野を宣言し、それが称号やプロフィールとして他者に見える形になる

ただし**「なぜ物語はスタートに戻るのか」の章が示すとおり、意志は最後に来ます。** 翻弄と成長が十分でないうちに意志を求めても機能しません。順番を飛ばさないこと。

## 決定した設計（2026年9月）

### 決定1：初回起動を無説明にする

ホーム画面もチュートリアルも出さず、**いきなり小学1年の問題を出す。**

- 1問目は**4択のみ**。マリオ1-1がまず「右に進める」を教えるのと同じで、基本形を先に見せる
- 3問目あたりで自由入力欄がすっと現れる。**説明はしない**。「こっちでも答えられるのか」と自分で気づかせる
- 数問解いたあと、初めてホーム画面が現れる

**「教わらずにできた」という体験から始まることが、教育を題材にしたこのゲームのテーマそのものです。**

### 決定2：選択肢を後出しにし、「選択と裁量」として設計する

問題画面は、自由入力欄と「選択肢を見る」を並べた状態から始まります。

```
┌─────────────────────────┐
│  答えを入力…             │
└─────────────────────────┘
        選択肢を見る          ← タップで4択が展開
```

- 難モードは**毎問、そこから始まる**。前の問題の状態を引き継がない
- **設定のトグルにはしない。** 設定にすると裁量が1回で終わるが、毎問にすると10回発生する。Bダッシュが常時判断させるのと同じ理屈
- 「4択に切り替える」はいつでも押せる。**降りるかどうかは常にプレイヤーの手にある**

なお、当初は難モードを自由入力にする案でしたが、入力コストと判定リスクの両方を抱えるため採用しませんでした。代わりに**タップ完結で判定リスクのない3方式**を、問題に応じて振り分けます（決定4）。自由入力はチャレンジバトルでのみ使います。

**リスクとリターン**

| | リスク | リターン |
|---|---|---|
| 自由入力 | 思い出せずに詰まる。時間がかかる | 当たれば最速。自分の言葉で言えたという確信 |
| 選択肢 | 見比べるので記憶に残りにくい | 確実。思い出せなくても解ける |

**リスクは時間と認知コストだけ。失点も減点もありません。** マリオがBダッシュに得点を与えないのと同じで、それで裁量として成立します。

### 決定3：報酬をプレイスタイルで差別化しない ★重要

**どちらの答え方でも、魔石・GUM・知識カードはすべて同一にします。**

理由：ゲーム内報酬をプレイスタイルで分けると、**「非効率的なプレイ」への忌避感が生まれます。** 学習するペースは人それぞれなので、選択肢を開くことが「サボり」に見える設計にしてはいけません。

したがって次を禁止します。

- 自由入力に報酬ボーナスを付ける
- **「自力回答率」のような統計を表示する**（出した瞬間に、選択肢を開くことが劣位に見える）
- 自由入力を推奨する文言を出す

差が出てよいのは**ゲーム外の報酬だけ**です。

1. **速さ** — 当たれば1タップ減る
2. **確信** — 自分の言葉で言えた、という手応え
3. **記憶への残りやすさ** — 再生（思い出す）は再認（見比べる）より定着する。学習科学の検索練習効果

3については、**一度だけ、中立な場所（ヘルプまたは設定の説明文）に一行だけ**置きます。促さない。事実として置くだけ。

> 選択肢を見ずに答えると記憶に残りやすいことが分かっています。ただし、どちらで答えても得られるものは同じです。

**判断材料を渡して、あとは本人に任せる。それが裁量です。**

### 決定4：難モードは3方式を問題に応じて振り分ける

現行480問にルーターを当てた結果です（`reading` 未設定の状態）。

| 難モード | 件数 | 備考 |
|---|---|---|
| `elimination` 消去法 | 416 | フォールバック。`reading` を足せば **234問が文字パネルへ回せる** |
| `numeric` 数値入力 | 53 | テンキー、単位は固定表示 |
| `range` レンジ | 11 | うち10問は既に `format: "range"` で実装済み |

**消去法は万能のフォールバック**です。4択さえあればどの問題でも成立するので、`reading` が無い問題は自動的にここへ落ちます。**段階的に `reading` を足していけるので、未整備のまま実装しても壊れません。**

**ルーターの決定順**（ビルド時に `hardMode` を焼き込み、`validate.mjs` が検査）

```
1. hardMode の明示指定があればそれに従う
2. 答えが数値（単位を分離できる）  → 数値入力
3. 答えが年・時代                  → レンジ
4. reading があり、かな2〜12文字    → 文字パネル
5. multi が定義されている          → 複数選択
6. 上記以外                        → 消去法
```

英字の答え（`for` など）は文字パネルから除外し、消去法へ回します。かなとアルファベットのパネルを混在させると操作が破綻するため。

#### 消去法

4択を出し、**正解を選ぶのではなく「違うもの」を3つ潰す。** 誤って正解を消したらそこで終了。既存データをそのまま使えます。ダミー選択肢が初めて働き始めるという副産物もあります。

**計算問題には割り当てないこと。** 正解を出した時点で他が違うのは自明なので、3回消す作業が冗長になります。

#### 文字パネル

| 読みの長さ | グリッド | ダミー |
|---|---|---|
| 2〜6文字 | 3×3（9マス） | 3〜7枚 |
| 7〜12文字 | 4×4（16マス） | 4〜9枚 |
| 13文字以上 | パネル不可 → 消去法へ |

**文字数の枠は表示しません。** グリッドしか見えないので、何文字なのかが事前に分からない。ここが4択との決定的な差です。

**経路生成**

1. ランダムなセルから、8方向隣接の自己回避経路を深さ優先＋バックトラックで長さLぶん引く
2. 経路順に読みの文字を置く
3. 残りセルにダミーを埋める（**1〜2枚は答えの文字を重複させて偽の分岐を作る**。ここが難易度のつまみ）

リトライ上限は100回。超えたら消去法へフォールバック。**この生成テストを `validate.mjs` に組み込み、通らない問題をCIで落とします。**

**操作**

- **1文字目のマークは出さない。** 探索コスト（9〜16マス）は許容範囲だが、マークは読みの1文字目を漏らしてしまう。たとえば「にんべん」で「に」が光っていたら、半分知っている人には答えそのものになる
- `pointerdown` → 隣接セルへ `pointermove` で経路を伸ばし、線で結ぶ
- 直前のセルへ戻ると1つ取り消し
- 上部に組み立て中の文字列をリアルタイム表示
- `pointerup` で確定。**指を離すまでは何度でもやり直せる**
- **セルの連続タップでも同じ入力が成立させる**（なぞれない状況でも片手で操作できるように）
- 小書き文字（ょ）と長音（ー）はそれぞれ1セル。カタカナ語はカタカナのパネル

#### 不正解時は、降りるかどうかをプレイヤーが選ぶ

**自動降下はしません。** システムがつまみを勝手に回すと、失敗が自分のものでなくなります。

不正解のとき、パネル（または数値入力）は**生きたまま**にして、下部に選択肢を並べます。

```
   ちがう。まだ続けてもいい。

   [ ヒントを見る ]  [ 4択に切り替える ]
```

プレイヤーの選択肢は3つです。**このまま挑み直す／ヒントを見る／4択に切り替える。** 1つ目は「何もしない」なので専用ボタンを置きません。押しても何も起きないボタンは、選択肢の重みを下げるだけなので。文言で3択であることを示します。

- 4択への切り替えは、その問題では不可逆。次の問題では難モードに戻る
- 切り替え先は素の4択（消去法ではない）。降りる方向であって横移動ではないため
- **どの経路で正解しても、魔石・GUM・知識カードはすべて同一**（決定3）

### 前提となる依存

**難モードが文字パネルと数値入力になったことで、表記ゆれ判定への依存は解消しました。** パネルは提示した文字しか使えず、数値入力は数値のみなので、判定は完全に機械的です。

ただし**チャレンジバトルは自由入力のまま**なので、受理集合の生成（漢字・かな・カナ・英語＋接尾辞バリアント）は依然必要です。**優先度を通常に戻すだけで、削除はしないこと。**

### ヒントの出し分け（対応済み）

選択肢が見えないモードでは、選択肢を潰す型のヒントが意味をなしません。**ヒントに `only` を付けてグループ分けする方式で解決しました。**

- `only: "choice"` … 4択・消去法のときだけ出す
- `only: "hidden"` … 文字パネル・数値入力・レンジのときだけ出す
- 無指定は両方で使う
- **どちらのグループでも3本そろっていること。** 足りなければヒントを増やす。`validate.mjs` がエラーで落とします

現行480問を走査した結果：**エラー3件、警告16件。**

エラー（hidden モードのヒントが正解そのものを含んでいる）は必ず直してください。

| 問題 | ヒント本文 |
|---|---|
| `sansu-018` | 「センチ」は百分の一を表すことば。センチ**100**枚でもとに戻る。 |
| `sansu-020` | 1キロメートルが**1000**メートルなのと同じ決まりだ。 |
| `sansu-061` | 4の倍数は 4、8、**12**、16…、6の倍数は 6、**12**、18… |

いずれも数値入力モードで答えを直接渡してしまいます。`only:"choice"` を付けたうえで、hidden 用のヒントを1本足してください。

警告16件（hidden モードのヒントが誤答に言及）は、**すべてが悪いわけではありません。** 誤答に触れていても知識として成立するものは残してよい。判断例：

- ✅ 残す — 「県は43ある。あとは足すだけだ」（43は誤答だが事実であり、43+4=47 の計算に導く）
- ✅ 残す — 「「こそ」だけが例外で已然形」（已然形は誤答だが文法知識として成立）
- ❌ 直す — 「18.84は直径×円周率、つまり円周の長さだから違うぞ」（純粋な選択肢潰し）

だからここは**エラーではなく警告**にしてあります。作問者が1件ずつ判断してください。
